# Data and Artifact Policy

## Purpose

Define what is source input data versus generated artifacts, and what should be version-controlled.

## Source Inputs (version-controlled)

- `structures/benchmark_entries.csv`
- `structures/experimental/`
- `structures/boltz/`
- `structures/vina/`
- optional curated subset CSVs in `structures/`

These files define benchmark identity and are considered source-of-truth inputs.

## Generated Artifacts (not source inputs)

- `output/` (benchmark CSVs, SQLite databases, analysis outputs)
- `.cache/` (normalized structures and cached contacts)
- temporary or preview plotting artifacts

Generated artifacts are reproducible from source inputs and scripts and should not be treated as source data.

## Publication-Facing Artifacts

Manuscript-facing derived files are generated by canonical scripts. If frozen release artifacts are needed for reviewers, keep them in a dedicated release folder and document provenance and generation command.

## Path Contract

- Inputs are referenced from pair CSV rows.
- Outputs are written under `output/`.
- Figures for manuscript are written under `manuscript/figures/`.

## Reproducibility Guidance

Always cite:

1. input pair CSV path
2. canonical commands used
3. output directory used
4. verification command result
